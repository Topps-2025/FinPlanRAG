# Introduction（统一版）

检索增强生成系统在金融问答中的困难，往往不只是从长文档中找到一个相关片段。以“截至某日，公司 A 是否通过某项交易控制资产 B”为例，系统可能需要区分直接主体与子公司，连接协议签署、先决条件和交割事件，并继续查找终止、处置或不控制条款。更关键的是，截止日后发布的完成公告虽然高度相关，却不能用于还原截止日当时可获得的认知。一个答案因此取决于多条候选关系路径是否分别闭合、限制证据是否被主动寻找，以及证据在何时有效、何时对公众可得。单纯提高段落相关性或扩大生成上下文，未必能解决这一规划问题。

已有 RAG 研究已经显著超越一次性检索。IRCoT 将推理与检索交错以处理知识密集型多步问题 [@trivedi2023ircot]；FLARE、Self-RAG 和 DRAGIN 分别利用生成置信度、反思信号与实时信息需要决定何时以及检索什么 [@jiang2023flare; @asai2024selfrag; @su2024dragin]；Adaptive-RAG 根据问题复杂度在无检索、单步和多步策略间路由 [@jeong2024adaptiverag]；EfficientRAG 进一步以关系识别驱动高效的迭代多跳检索 [@zhuang2024efficientrag]。Search-R1 等工作也表明，多轮搜索策略可以通过结果奖励学习 [@jin2025searchr1]。因此，“现有 RAG 不会规划复杂问题”并不是成立的 research gap。

与本文最接近的是金融和时间检索研究。TimeR4 对时间约束进行重写、检索与重排 [@qian2024timer4]；HiREC 在大规模 SEC 文档上结合层级检索、passage filter、answerability checker 和 complementary question generator，已经能够在证据不足时继续补证 [@choe2025hirec]。FinSearchComp 则用专家构造的多源、时间敏感问题显示，浅搜索、过时证据与来源冲突确实是现实金融搜索系统的失败模式 [@hu2025finsearchcomp]。与此同时，Sufficient Context 表明，即使上下文不足，强模型仍可能给出错误回答，并指出迭代形成充分上下文与选择性生成之间尚有研究空间 [@joren2025sufficientcontext]。这些工作分别覆盖了时间检索、金融补充查询和充分性判断，也进一步要求本文把创新主张限定得更精确。

本文研究的待验证缺口不是多轮检索本身，而是点时金融关系任务中的规划状态与评价单位。现有主动或智能体 RAG 通常以自然语言推理轨迹、模型不确定性、问题级 answerability 或最终结果奖励驱动后续搜索；现有文献尚未在该任务和表示下系统检验一种显式、可审计的状态，它同时区分独立关系路径、机制特定的证据义务、限制证据、来源谱系、事实有效时间与公众可得时间，并直接据此选择下一动作以及继续、断言或拒答。这里的“尚未检验”并不意味着已有方法原则上无法扩展；它构成的是一个可由强基线否证的任务—表示假设。

为检验这一假设，我们提出 FinPlan-RAG，将金融关系问答表述为受约束的序贯检索决策。系统在第 (i) 步维护

\[
S_i=(\Pi_i,O_i,C_i,L_i,T_i,P_i,b_i),
\]

其中 (\Pi_i) 表示候选关系路径，(O_i) 表示尚未闭合的证据义务，(C_i) 与 (L_i) 分别表示冲突和限制证据，(T_i) 区分有效时间与可得时间，(P_i) 记录来源谱系，(b_i) 为剩余预算。关系模板只定义最低证据义务和合法动作，不编码最终答案或固定动作顺序；规划器在检索指定槽位、搜索限制证据、扩展实体/路径、核验时间/冲突以及断言/拒答之间选择。每轮证据只有在通过主体、关系、时间和谱系验证后才能更新状态。

我们设计 FinRel-PT 作为真实数据检验载体。其首版从 SEC EDGAR 的 8-K、10-K、10-Q 及交易附件中构造收购/控制关系的历史回放问题，以 accession 和 `acceptanceDateTime` 固定证据的公众可得时点，并将同一交易的签署、修订、完成与终止材料按 lineage 成组切分。中国轨道则复用 FinGLM 公开年报与人工问答，并从巨潮资讯、上交所和深交所公开披露补建混合报告期、问询回复、并购进展和监管整改链。测试集不仅标注最终关系状态，还标注候选路径、证据义务、支持/限制证据跨度、来源谱系与停止条件。公开原题和自行构建题分开报告；LOFin/HiREC、FinSearchComp、MultiHop-RAG 和时间问答数据用于辅助评价，不替代点时过程标签。

方法的适用范围不限于收购。FinPlan-RAG 将金融任务组织为生命周期关系、会计推导、点时指标和比较调查四类模板：它们共享路径/分支、证据义务、冲突、双时间、谱系与预算状态，但分别定义协议终局、计算组件、数据 vintage 或跨实体对齐等闭包规则。这里的“通用”只指金融域内的机制复用，不是面向任意领域的通用 agent，也不意味着所有轨道共享同一查询模板；只有至少两条真实轨道在非 oracle、端到端冻结测试中显示状态接口的独立增益，论文才使用金融域通用性主张。

当前实验只形成分层诊断证据。SEC 生命周期回放显示，移除公众可得时间会在探索/留出样本产生 58.8%/41.7% 的未来信息泄漏。LOFin 关联的真实 10-K 轨道则在 BM25、dense 和 hybrid 条件下复现无路径闭包缺口；然而路径绑定 FinPlan 与元数据和 Generic 强基线持平。进一步移除 oracle 路径后，第三批 company/file-OOD 冻结测试中，旧规则和 v4 分别闭包 15/22 与 18/22，双侧 exact McNemar p=.25，尚不足以支持稳定方法优势。更关键的是，在公司与文件均不重叠的 8 题、21 文件混合 10-K/10-Q 冻结集上，实体—年份版 v6 虽正确识别全部主体，显式义务召回却为 0、闭包仅 4/8；FinPlan v3 路径绑定为 5/8，低于 HiREC-style 路径绑定的 7/8。该结果把 gap 定位为同年多 filing 的义务键碰撞，同时否定了当前 FinPlan 已领先的主张。

据此，现行候选框架将文件义务从实体—年份扩展为实体、filing type、财政年度与财政期间的组合，并把 Q4 证据映射到 FY 10-K。在参与开发的混合 filing 数据上，v7 的义务与文件闭包回放达到 8/8；但在随后冻结的 8 题、14 文件 validation6 上仅为 6/8，与 period metadata decomposition 持平，低于 Generic/HiREC-style period 的 7/8。三道多 filing 题虽均闭包，样本仍不足。中国公开轨道进一步在 9 道 FinGLM 跨年题、18 份巨潮官方年报和 3,567 页语料上完成冻结 pilot：测试集上 entity-only FinPlan 闭包为 0/5，扩展为 entity-year 后为 5/5，但 metadata decomposition、Generic 和 HiREC-style 也均为 5/5；Single-shot 虽闭包 5/5，错误文档率为 0.4667。这一结果支持跨年义务原子化，却没有证明 FinPlan 的策略优势，而且同质化题型尚不足以检验混合期间、限制证据与点时拒答。真实 LLM reader、原版 HiREC/Search-R1、国内机制数据集以及继续/断言/拒答决策仍未完成，因此本文当前不能声称 SOTA 或完整算法贡献。

实验围绕五个问题展开：真实系统在高原子证据召回下是否仍有路径混淆、限制证据遗漏和未来信息泄漏；主体—类型—财政年度—期间义务是否避免同年 filing 碰撞；显式状态在共享模板、检索器、模型与预算时是否具有独立价值；学习型规划是否超过固定关系规划、HiREC 风格补充检索和通用结果奖励 agent；以及状态驱动停止能否改善 coverage–risk，而非只通过增加拒答或检索预算获得表面收益。主结果同时报告答案质量、路径/义务闭包、限制证据召回、future leakage、校准与查询成本，并以 company-OOD、time-OOD 和 filing-type-OOD 切分检验泛化。

本文的贡献将由实验结果分层裁决，而非预先宣称。若真实实验通过预注册门槛，贡献包括：（1）点时金融关系证据规划任务与过程级 benchmark；（2）可供不同 RAG 策略共享的关系证据状态和合法动作接口；（3）在统一骨干条件下对固定、主动、智能体与学习型规划的因果比较；（4）联合答案、限制证据、历史泄漏、coverage–risk 与成本的评价协议。若学习策略不能超过固定规划，论文将删除算法优越性主张；若显式状态也不能改善风险—成本前沿，则工作收缩为 benchmark 与审计协议。
