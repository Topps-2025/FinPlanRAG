# 论文大纲

## 暂定标题

中文：**FinPlan-RAG：面向点时金融关系问答的证据状态检索规划**

英文：**FinPlan-RAG: Evidence-State Retrieval Planning for Point-in-Time Financial Relation Question Answering**

若最终只完成收购/控制数据，应将标题中的 *Financial Relation* 收窄为 *Acquisition and Control Relation*。

## 摘要逻辑

1. 问题：金融多跳问答不仅需要找到相关文档，还要沿独立关系路径闭合证据、检索限制证据并遵守历史认知 cutoff；
2. 缺口：通用主动/智能体 RAG 和金融 HiREC 已能动态补证，但尚未在该任务中系统评价显式关系证据状态；
3. 方法：FinPlan-RAG 用路径、义务、冲突、限制证据、双时间、谱系和预算构造状态，并在受约束动作空间中规划；
4. 数据：基于 SEC EDGAR 的点时交易 lineage benchmark，并用 LOFin、FinSearchComp 等作外部测试；
5. 结果：填入真实实验的答案、固定覆盖风险、限制证据召回、future leakage 与成本，必须同时报告负结果；
6. 结论：只按 Go/No-Go 结果选择算法、状态接口或 benchmark 定位。

## 1 Introduction

- 以“签约—条件—完成/终止—子公司链”的点时例子说明普通相关性检索为何不等于关系成立；
- 承认 IRCoT、FLARE、Self-RAG、Adaptive-RAG、DRAGIN、EfficientRAG 已解决多种动态检索问题；
- 承认 HiREC 已在金融 SEC 语料中实现充分性检查与补充问题；
- 将 gap 限定为显式、可审计的关系证据状态及其过程级评价；
- 给出研究问题、方法、真实数据与经过实验裁决后的贡献。

## 2 Related Work

### 2.1 Active and adaptive RAG

FLARE、Self-RAG、Adaptive-RAG、DRAGIN：重点比较触发信号、状态粒度和停止机制。

### 2.2 Multi-hop and agentic retrieval

IRCoT、EfficientRAG、Search-R1、MultiHop-RAG：区分自由文本轨迹、通用关系路径和本文证据义务状态。

### 2.3 Temporal and selective RAG

TimeR4、Sufficient Context：区分事实时间与公众可得时间，并连接充分上下文与选择性预测。

### 2.4 Financial search and RAG

HiREC/LOFin、FinSearchComp：将本文定位为紧邻其后的任务/表示扩展，而非声称金融 agent 从未规划。

## 3 Task and Benchmark

### 3.1 Point-in-time financial relation QA

定义 query contract、关系标签、abstain 行为、valid time 与 available time。

### 3.2 FinRel-PT construction

SEC 来源、交易 lineage、正负闭包、限制证据、标注协议与去泄漏切分。

### 3.3 Financial template registry

生命周期关系、会计推导、点时指标和比较调查共享状态字段，但分别定义义务、合法动作与停止条件；报告哪些轨道完成端到端验证。

### 3.4 Process annotations

候选路径、证据义务、跨度、限制证据、谱系、动作与停止标签。

## 4 Method

### 4.1 Explicit evidence state

定义 (S_i=(\Pi_i,O_i,C_i,L_i,T_i,P_i,b_i))。

### 4.2 Relation-constrained action space

定义 slot、limit、entity/path expansion、time/conflict verification、assert/abstain。

### 4.3 Planning policy

先报告固定 value-of-information planner；仅在真实 pilot 支持后加入行为克隆/偏好优化策略。

### 4.4 Verification and stopping

证据写入、时间过滤、谱系去重、冲突处理与 coverage–risk 校准。

## 5 Experiments

### 5.1 RQ1: failure prevalence

控制原子证据召回后统计路径混淆、限制证据遗漏与 future leakage。

### 5.2 RQ2: explicit-state value

比较自然语言轨迹、二元 answerability、same-state generic agent 与 FinPlan-RAG。

### 5.3 RQ3: learned vs fixed planning

统一骨干下比较 fixed planner、HiREC-style、Search-R1-style 和 learned planner；做 company/time/relation OOD。

### 5.4 RQ4: selective stopping

报告 coverage–risk、AURC、固定覆盖风险、固定风险覆盖和校准。

### 5.5 Ablations and stress tests

逐项移除路径、义务、限制证据、available time、谱系、冲突动作、停止和学习策略。

### 5.6 Efficiency and error analysis

查询/token/延迟/成本；逐例分析真实规划增益、检索瓶颈和不合理拒答。

### 5.7 Cross-template transfer

至少比较生命周期关系与一条会计/指标/调查轨道；若只在 SEC 收购链有效，删除“金融域通用”。

## 6 Discussion

- 金融关系模板的收益、人工成本与可迁移性；
- 结构状态是否优于给通用 agent 更多上下文；
- benchmark 的美国监管披露偏差；
- 不能将文档证据等同法律意见或投资建议；
- 对未来模型训练数据记忆与测试污染的局限。

## 7 Conclusion

只总结被真实实验支持的层级：算法策略、显式状态，或 benchmark/审计协议。不得从受控仿真外推真实金融优越性。
