# FinPlan-RAG 研究总图

## 核心问题

> 当金融问题需要跨主体、关系、文档和时间获取证据时，显式维护“还缺什么、哪条路径未闭合、是否存在限制证据、当前信息在截止时点是否可得”，能否改进 RAG 的下一步检索与停止决策？

## 统一论证链

```mermaid
flowchart LR
    A["金融多跳关系问题"] --> B["通用主动/智能体 RAG"]
    B --> C["自然语言轨迹或二元充分性"]

    D --> E["关系约束的证据状态"]

    H -->|继续| F
    H -->|结束| I["可审计答案与轨迹"]
```

## 当前裁决

- 保留：点时合同、显式证据状态、关系约束动作空间、继续/断言/拒答、限制证据轨道；
- 已获 pilot 支持：SEC 真实回放中的 future leakage 和检索轨迹污染；LOFin 真实 10-K 实验中，无路径绑定方法的文件闭包缺口跨 BM25、BGE dense 与 RRF hybrid 复现；第三批 company/file-OOD 中，非 oracle v4 相对旧规则由 15/22 提高到 18/22，但 p=.25，尚不显著；
- 已确认的表示瓶颈：在 8 题/21 文件的混合 10-K/10-Q 冻结集上，实体—年份规划的义务召回为 0，冻结非 oracle v6 闭包 4/8；同年多季度被折叠为一个状态节点。FinPlan v3 路径绑定为 5/8，弱于 HiREC-style 路径绑定的 7/8；
- 架构迭代：现行开发版 v7 将义务键扩展为“主体、filing type、财政年度、财政期间”，在已观察混合 filing 错误上回放为 8/8。该结果参与了开发，不能作为确认性优势；
- 新冻结反证：validation6 含 8 题、14 份未使用文件、8 家公司。v7 闭包 6/8，period metadata decomposition 为 6/8，Generic/HiREC-style period 均为 7/8；三道多 filing 题都闭包，但样本仅 3。当前不能主张 v7 超过同元数据强基线；
- 国内公开 pilot：9 道 FinGLM 跨年题、18 份巨潮官方年报和 3,567 页语料已完成冻结运行。测试集上 entity-only FinPlan 闭包 0/5，entity-year 为 5/5，但 metadata decomposition、Generic 和 HiREC-style 同为 5/5；这复现了义务表示不足，却没有证明策略优势。两条姓名金标存在简繁字形/大小写伪差异，已与 RAG 错误分开审计；
- 国内自建机制轨道：FinGLM2 只有问题和 schema，不能冒充完整 benchmark。首批同年 H1/Q3/FY 期间碰撞协议已冻结 5 家公司，并取得 10 份巨潮 H1/Q3 报告，尚未运行方法；后续继续构建问询—回复、并购进展和处罚整改链，并保存 `valid_time`、`available_at`、`cutoff`、限制证据与拒答标签；
- 待真实验证：真实 reader/LLM、原版 HiREC/Search-R1、国内混合期间与公告链，以及基于闭包状态的继续/断言/拒答是否仍有独立增益；
- 不进入核心：开放概念发现、叙事漂移、市场收益与组合回测；
- 失败收缩：若强补充检索在获得相同 filing 元数据后追平，算法主张收缩为义务表示、benchmark 和审计协议。
