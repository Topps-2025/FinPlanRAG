# FinPlanRAG 当前进度与后续实验

## 1. 当前论文定位

本文研究的不是“现有 RAG 不会多轮检索”，而是一个可证伪的任务—表示假设：在金融多跳问题中，显式维护独立证据路径、未闭合义务、限制证据、来源谱系、事实有效时间和公众可得时间，是否能改善下一步检索以及继续、断言或拒答决策。

当前允许的主张是：

> filing/period-aware 义务表示缺口已经在真实美国与中国金融任务中出现，但当前尚未证明 FinPlan 的动作策略相对同元数据强基线具有独立优势。

这里的“尚未在该任务和表示下验证”不是“现有 Agentic RAG 原理上做不到”。若 Generic 或 HiREC-style 方法获得相同金融元数据后追平，论文必须删除策略优越性主张。

## 2. 已完成的 research-gap 证据

### 2.1 SEC 点时关系轨道

- 15 条真实 SEC 交易 lineage 的历史回放已复现 future leakage；移除 `available_at` 后，探索/留出样本泄漏率为 58.8%/41.7%。
- 原始 FinPlan v1 曾弱于通用自适应与 HiREC-style 诊断；加入路径绑定后在小样本上改善，但不足以证明 SOTA。
- 该轨道说明公众可得时间、路径串线和限制证据是实际问题，不只是合成设定。

### 2.2 LOFin/SEC 多文档轨道

- 无路径绑定的文件闭包缺口已跨 BM25、BGE dense 和 RRF hybrid 复现。
- company/file-OOD 非 oracle 测试中，旧规则闭包 15/22，v4 为 18/22，exact McNemar `p=.25`，方向改善但不显著。
- 混合 10-K/10-Q 冻结集暴露实体—年份状态碰撞：主体识别 8/8，但义务召回为0、闭包4/8；同公司同年不同 filing 被错误折叠。
- filing/period-aware v7 在新冻结 validation6 上闭包6/8；period metadata decomposition 为6/8，Generic 和 HiREC-style period 均为7/8。
- 自建 validation7（LOFin 无新鲜同公司多 filing 来源，6 新公司 × 5 文件 = 30 份此前未用 SEC 文件，18 题 dev 4/frozen 14）：冻结 14 题上 v8（v7 + 预声明半年度别名 H1→Q2、H2→Q3+FY）闭包 11/14，显著高于 v7 5/14、metadata 5/14 与 entity-year 3/14（配对精确 McNemar p≈.02–.03）；错误文档显著低于 Single-shot/HiREC-style（p≤.001）；相对 Generic/HiREC-style 闭包 11 vs 8 仅方向有利（p=0.25）。v8 增益全部来自别名层；h2 推导题对非 v8 方法全败。负结果：跨年度边界层（fy_q1n）三题所有方法全败（"fiscal year N" 未进入义务键）；h1_9m 过度检索 Q1。
- 因此表示缺口真实存在；期间别名映射在冻结集上首次显著超过同元数据分解基线，但相对两个强改进基线的闭包差异仍只有方向性，不能声称 SOTA。
- **A4（–Available time）消融已在同一冻结集上运行**（2026-08-11，预声明 freeze → dev 诊断 → frozen 14 一次性，time 变体与冻结结果 0 差异）：移除 available_at 约束后，v8 在 case 级逐字段不变（0/14 未来泄漏、闭包 11/14 不变），其防泄漏是结构性的（显式期间解析 + 路径绑定），不依赖时间门；Single-shot 10/14 泄漏（p=0.002）且闭包 8→4，Generic/HiREC 7/14（p=0.016），metadata 分解 3/14（经 planning 层 annual fallback 取未来 10-K——预声明 P3 被证伪，如实记录）。no_time 体制下 v8 闭包显著超过 Single-shot（11 对 4，p=0.016），但正式优势主张仍受时间门开启时主对比（p=0.25）约束。A3 在本轨道无 L 机制可删（SEC pilot 的 finplan_no_limit 已有证据）；A5/A6 因载体数据（中国问询/并购链、比较调查轨道）未构建，仍不可执行。
- **自建 validation8 已运行**（2026-08-11，预声明 manifest + freeze → dev 6 诊断 → frozen 24 一次性，6 家全新公司 CSX/CVS/GD/TXN/CMCSA/HCA × 5 文件 = 30 份此前未用 SEC 文件，54 条 XBRL+文本双验证）：v9（v8 别名 + fiscal-year-N 解析 + first-n 只取 Qn）闭包 24/24、wrong_doc 0.000，显著高于四个 v7-shared baselines（10–11/24，配对精确 McNemar p≤0.00024，全部非平局配对单侧）——validation7 的 p=0.25 方向性在 n=24 上成为显著；fy_q1n 层 5/5（v8 0/5，P1 确认）、h1_9m 错误文档 0.000 vs v7/v8 0.333（P2 确认）。**P4 诚实性对照（同义务、检索退化为元数据分解 fill_missing）24/24 与 v9 完全持平**——按预声明边界，论文的策略优势主张必须收缩到表示层（期间解析），级联检索策略无独立于表示的增益。future_leak 0/24，dev↔frozen 确定性 0 差异。审计：`lofin_validation8_statistical_audit_v1.json`。
- **公共 LOFin 完整 1,572 题 × 9 方法全集已一次性运行并冻结**（2026-08-11/12，协议 `lofin_full_benchmark_protocol_v1.json` + amendment_3 提交 16cca23；470 组、14,148 行、BUDGET=4，dev↔frozen 确定性 0 差异；两次 MemoryError 崩溃按范围恢复后由磁盘吸收补全，无重跑）。全集闭包（full 层）：v9_cascade / v8 / v7 / period_metadata_decomposition 均为 **0.892–0.895** 且互不显著（36 对精确 McNemar 中该组内部 disc=11、p=0.227）；v9 vs generic_adaptive_period 打平（39/40 胜、p=1.000）；v9 显著高于 hirec_period 0.859（p=0.0001）、single_shot 0.642（p<0.001）与 v4 0.577（p<0.001）。错误文档率：planner 系 0.31–0.32 显著低于 single_shot 0.80 / hirec 0.62 / generic 0.47（均 p<0.001）。**义务精确匹配 obligation_exact 仅 0.45–0.46**——文件级闭包 ≠ 答案准确率，全集上仍差很远。**预声明 P2（v9 在 fiscal-year 措辞层优于 v8）被证伪**：该层 v9 闭包 0.821 < v8 0.875，配对 v9 胜 0/3（n=56、p=0.25）；P1（开放问题低闭包）成立（全集 0.577–0.895 远未饱和）；P5（命名表面）方向支持（0.935 vs 0.850）；**P4/P6 复现 validation8：metadata_v9_fill 与 v9 完全持平（36 对中 disc=0、p=1.000）**，级联检索确无独立于表示的增益。未来泄漏：planner 系 5 个 runner 各 1 个 case（非 0，如实记录；baselines 经 used_docs 口径为 0）。完整分层表与 36 对 McNemar 见 5.13 节与 `lofin_full_benchmark_audit_v1.json`。

### 2.3 中国 FinGLM 公开轨道

- 已核验 FinGLM 11,588 份2019—2021年年报清单与复赛A 2,000题/答案；FinGLM2 有101组、311个子问题，但数据库和金标答案未公开，不能冒充完整 RAG benchmark。
- 9道跨年题、18份巨潮官方年报和3,567页语料已完成冻结 pilot。
- 冻结5题中，原始 entity-only FinPlan 闭包0/5；entity-year 扩展后为5/5，但 metadata decomposition、Generic 与 HiREC-style 也均为5/5。
- Single-shot 闭包5/5，但错误文档率为0.4667，说明其高召回依赖额外噪声。
- qid 357 和1493分别存在姓名简繁字形、英文大小写伪差异；原始标签和规范化语义标签已分开保存，不归因于 RAG。

中国公开 pilot 因题型同质、每题只有两个目标年份，只验证义务原子化的必要性，不足以验证完整 research gap 或方法优势。

## 4. 方法状态和优化空间

原框架已经出现两类需要修正的问题：

1. `entity-only` 或 `entity-year` 义务键会折叠独立年度/期间；
2. period-aware FinPlan 即使修复表示，也没有超过拥有相同元数据的 Generic/HiREC-style 基线。

下一版优先优化规划状态和动作策略，而不是继续调 BM25：

- 义务扩展为“主体/证券代码、文档类型、财政年度、财政期间、指标或关系槽位、cutoff”；
- 增加同公司同年多文档 collision 检测；
- 区分主体识别失败、期间映射失败和证据检索失败；
- 保留独立路径和限制证据动作，并用相同 metadata、语料、模型和预算比较；
- 分开报告义务闭包、文件闭包、页级证据闭包、真实 reader 正确率和停止/拒答质量。

validation7 暴露、validation8 预声明确认的 v9 修改（全部在 manifest 冻结后才运行方法，未在已运行冻结集上改动）：

- "fiscal year N"（以及 H1/H2 之外的自然期间短语）进入 period 解析，修复 fy_q1n 层 0/3——**validation8 确认**：fy_q1n 5/5（v8 0/5）；
- "first n quarters" 改为只取 Qn 所在累积文件，消除 h1_9m 的 Q1 过度检索——**validation8 确认**：h1_9m wrong_doc 0.000 vs v7/v8 0.333；
- 半年度别名映射（H1→Q2、H2→Q3+FY）已在 validation7 冻结集确认，validation8 保持默认表示——**维持确认**。

validation8 同时给出诚实负结果：与 v9 共享义务、仅检索退化为元数据分解 fill_missing 的对照（P4）闭包与 v9 完全持平（24/24），即级联检索策略在本轨道无独立于表示的增益——论文的策略优势主张只落在表示层（期间解析），不落在动作策略。

只有开发集失败可以用于改架构；修改后必须在未观察的公司/公告链冻结集确认。若强基线继续追平，贡献收缩为金融证据义务表示、多场景 benchmark 和可审计协议。

## 5. 金融域通用性的边界

FinPlanRAG 不限于收购，但“通用”只指金融域内共享状态接口。目前规划四类场景：

1. 生命周期关系：并购、控制、许可、供应关系的签署—条件—完成/终止；
2. 会计推导：定义—组件—期间—单位—计算；
3. 点时指标：报告类型、财政期间、data vintage 与截止时点；
4. 比较调查：跨公司/跨年度对齐、共同定义和来源冲突。

至少两条真实、非同源轨道在非 oracle 端到端冻结测试中显示共享状态接口的独立增益后，论文才使用“金融域通用”表述；不声称优于任意领域的通用 agent。

7. 根据 Go/No-Go 裁决论文最终形态。

## 8. 当前结论

Research gap 已获得部分真实证据：金融多跳任务确实暴露路径串线、期间义务碰撞和点时泄漏。期间表示层（自然期间措辞 + 别名 + 跨年度边界解析）已在两个独立冻结集上被确认是真实且必要的：validation7 别名层（p≈.03）、validation8 冻结 24 题上 v9 相对 v7-shared baselines 的闭包优势首次显著（p≤0.00024）。但**公共 LOFin 完整 1,572 题全集（2026-08-12 冻结）给出了更强制的校准**：全集上 v9/v8/v7/period_metadata_decomposition 闭包均为 0.892–0.895 且互不显著，v9 vs generic_adaptive_period 打平（p=1.000）——validation8 的表示层优势未能在全集上保持为显著；v9 相对 public baselines 中真正稳健的增益只剩错误文档率（0.31 vs single_shot 0.80 / hirec 0.62）与对 hirec/single_shot/v4 的闭包优势；义务精确匹配仅 0.46，文件级闭包 ≠ 答案准确率。全集同时确认 validation8 的两条负面证据：预声明 P2（fiscal-year 措辞层 v9>v8）被证伪（v8 反而更高），metadata fill 与 v9 完全持平（disc=0），**级联检索策略无独立于表示的增益**。因此”FinPlan 动作策略优于现有改进方法”仍未成立，论文的策略优势主张必须收缩到表示层，且表示层的全集增益主张需按上述口径如实陈述（分层、非全集整体）。后续实验的价值是回答：哪一种动作策略能在公平强基线下真正产生独立增益（目前唯一候选是错误文档率），以及中国机制轨道能否在更广场景复现表示层证据。
