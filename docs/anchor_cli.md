# FinPlanRAG 的 AnchorEvolve CLI 与 Claude Code 接口

这个接口把论文中 FinPlanRAG 的 AnchorEvolve 模块流程做成一个可以在本地运行的命令行工具和 MCP 服务。它面向的是尚未披露结果的前瞻性金融断言，例如某家公司下一年度年报的营业收入增速、归母净利润增速、毛利率，或者年报预计在哪一天披露。系统的输出不是一句没有依据的判断，而是一条可以逐项检查的证据链：问题被写成断言契约，证据按截止时点过滤，锚点必须引用原文并经过资格判定，信念更新和动作选择都保留中间状态。

## 1. 运行方式

依赖：

```bash
pip install -e ".[agent]"
```

`.env` 中只需要放 DeepSeek 的 Anthropic 兼容配置，密钥不会写入代码、日志或审计文件：

```text
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
ANTHROPIC_MODEL=deepseek-flash[1m]
ANTHROPIC_AUTH_TOKEN=<your-key>
```

运行内置案例：

```bash
python scripts/anchor_cli.py case zhongji_2026 --cutoff 2026-11-19
python scripts/anchor_cli.py case xinyisheng_2026 --cutoff 2026-11-19
```

运行消融版本时，使用显式开关而不是另写一套配置：

```bash
python scripts/anchor_cli.py case xinyisheng_2026 --no-bridge
python scripts/anchor_cli.py case xinyisheng_2026 --no-calibration
```

运行自然语言问题：

```bash
python scripts/anchor_cli.py ask \
  "中际旭创2026年年报营业收入同比增速会落在什么区间？" \
  --company 中际旭创 --ticker 300308.SZ --period 2026年年度报告 \
  --cutoff 2026-11-19
```

查看某次运行的审计报告：

```bash
python scripts/anchor_cli.py audit 20261119-162745-zhongji_2026-d677
```

只检索证据、不做推断：

```bash
python scripts/anchor_cli.py search "中际旭创 2026年三季报 毛利率"
```

## 2. Claude Code 集成

项目根目录的 `.mcp.json` 已经注册了一个 stdio MCP 服务：

```json
{
  "mcpServers": {
    "finplan-anchor": {
      "type": "stdio",
      "command": "python",
      "args": ["scripts/run_anchor_mcp.py"]
    }
  }
}
```

在项目目录启动 Claude Code 后，用 `/mcp` 确认 `finplan-anchor` 已连接。服务提供五个工具：

| 工具 | 用途 |
|---|---|
| `anchor_ask` | 对自然语言问题做完整裁决，返回动作、点答案、裁决集或弃权 |
| `anchor_case` | 运行 `configs/anchor_cases` 下的具名案例 |
| `anchor_search` | 检索带日期的网络证据 |
| `anchor_audit` | 读取某次运行的完整审计报告 |
| `anchor_contract` | 只把问题解析成断言契约，便于先检查阈值和结果空间 |

可以直接对 Claude Code 说：

```text
请用 finplan-anchor 的 anchor_case 工具运行 zhongji_2026，
截止时点设为 2026-11-19，然后逐条解释每个断言的证据链和动作。
```

或者：

```text
用 anchor_ask 评估中际旭创2026年年报的营业收入增速和披露日期，
截止时点 2026-11-19，并告诉我哪些证据被采纳、哪些被拒绝。
```

Claude Code 负责对话和工具编排，DeepSeek 负责问题解析和锚点抽取。两条路径调用的是同一个 `anchor_engine`，因此终端运行和 Claude Code 运行生成同样的审计文件。

MCP 服务在 Claude Code 启动时加载 Python 模块。修改 `anchor_engine.py`、提示词或案例文件后，需要重启会话或重新连接 `finplan-anchor`，否则工具仍在旧进程里运行旧代码。可以用 `python scripts/run_anchor_mcp.py` 手动启动一个新进程做对照。

Codex CLI 使用同一个 MCP 服务，项目级配置在 `.codex/config.toml`，工具名为 `mcp__finplan-anchor__anchor_case` 等。完整说明和 DeepSeek 模型配置见 [codex.md](codex.md)。

## 3. 处理流程

```text
问题
  -> 断言契约（公司、期间、指标、结果空间、阈值、检索词）
  -> 时点证据（官方公告记录 + 网络检索，按 cutoff 过滤）
  -> 锚点抽取（LLM，必须引用 W# 原文）
  -> 资格判定（vacuous / stale / adversarial / hard / soft）
  -> 信念更新（按锚点类型可靠性加权）
  -> 全动作损失感知读出（点答案 / 裁决集 / 弃权）
  -> 审计报告（JSON + Markdown）
```

### 断言契约

每个断言有明确的标签集合和阈值。以 `zhongji_2026` 为例：

| 断言 | 标签 |
|---|---|
| 营业收入同比增速 | 低于140% / 140%至170% / 高于170% |
| 归母净利润同比增速 | 低于190% / 190%至220% / 高于220% |
| 综合毛利率 | 低于45% / 45%至47% / 高于47% |
| 年报披露日期 | 不晚于2027-03-31 / 2027-04-01至2027-04-15 / 晚于2027-04-15 |

阈值来自 2025 年实际值和 2026 年已披露的三季报，写在案例文件中，不在代码里写死。自然语言问题由解析器生成契约；如果用户没有给出数值阈值，解析器会退化为定性标签，审计报告会给出提示。

### 时点证据

证据有三个来源：

1. 巨潮资讯网的深交所公告记录。对披露日期断言，系统查询 `category_ndbg_szsh`，得到历年年报的公告日期和 PDF 链接。对数值指标断言，系统查询 `限制性股票` 与 `业绩预告`，优先抓取目标年份的激励计划草案或摘要，并从中提取全年营业收入目标。官方记录优先级高于媒体文章。
2. Sogou、360、百度的网页检索。三个提供者轮换使用，某个提供者返回空结果时自动回退，避免单一搜索引擎的安全验证页让整次运行静默失败。
3. 媒体、研究报告和公司公告的转载。系统要求逐字引文，并对无日期来源降权。`baijiahao.baidu.com/s?id=` 属于内容页，不再被误判为百度搜索结果页。

检索词采用**查询面组合**，而不是一张扁平列表：`latest_period`（最新季报/年报）、`prior_period`（上一年度实际值）、`forward_disclosure`（业绩预告、股权激励、限制性股票、投资者关系）、`industry`（行业趋势）、`date_disclosure`（年报披露日期）。每个查询面有 `required` 标记，预算分配时先给每个必需查询面至少一条，再给解析器查询和可选查询面。解析器自带查询被限制为最多两条，避免泛化查询挤掉必需查询面。

如果某个必需查询面在最终证据中没有命中，审计报告会记录 `coverage_gaps`，而不是静默地把它当成“没有证据”。这样，换一个指标或行业时，用户可以看到哪个查询面缺证据，再决定增加该查询面的模板或提高预算。

所有证据在进入锚点抽取前按截止时点过滤。晚于截止时点的来源被写入审计报告的“被剔除的证据”。图片页、文库页、短视频页不作为文档证据。

证据选择采用按查询轮转：每个查询至少贡献一条，再按得分补齐，防止一个查询的五篇近重复报道占满全部名额。官方公告证据排在最前。长公告不直接截取前 N 个字符，而是先抽取包含指标、财务词和“亿元/%”等数值单位的句子，避免把深埋在公告中的考核目标截掉。

### 锚点与资格判定

锚点必须包含 `source_id`、逐字引文、发布日期、可靠性、隐含标签和理由。系统做以下确定性检查：

- 来源编号必须存在于本次证据集合，否则判为 adversarial。
- 锚点日期或来源日期晚于截止时点，判为 stale。
- 引文必须能在来源文本中逐字匹配；未匹配的锚点降权，且不能成为硬锚点。
- 来源日期未知的锚点可靠性上限为 0.55，且不能成为硬锚点。
- 对增速类断言，只描述上一年度参考值的锚点判为 vacuous，不进入信念更新。
- 对披露日期断言，泛泛的法定截止日判为 vacuous，因为它不能区分三个日期窗口。
- 对披露日期断言，如果锚点提到的日期与隐含标签不一致，系统按“月日投影到目标年份”的规则纠正标签，并记录纠正原因。
- 对披露类断言，“某季度营业收入”不能证明“公司没有发布指引”。负向披露标签需要明确的“未发布/未披露”语句；只有季度结果、没有指引语句的锚点判为 vacuous。
- 引文核验同时对照证据全文、送入提示词的摘录和搜索摘要，避免公告 PDF 全文超过审计存储上限时把真实引文误判为未通过。

硬锚点需要同时满足：模型标记为 hard、可靠性不低于 0.80、引文逐字通过、来源日期已知、且不存在时间一致性疑点。硬锚点在融合 LLM 标签分数之后再次投影到可行集，避免 0.5 的融合权重把硬约束稀释成 0.8 左右的普通高概率。

### 信念更新与读出

每个软锚点按隐含标签构造似然，指数为锚点可靠性；硬锚点把信念压到隐含标签上并保留小底。锚点后验再与 LLM 的标签分数按配置权重融合。读出在三个动作上计算期望损失：点答案、非单元素裁决集、弃权。单元素裁决集与点答案语义重复，因此裁决集只允许两个及以上标签。损失参数在 `configs/anchor_cli.yaml` 中给出。

## 4. 中际旭创案例

2026 年 11 月 19 日的运行结果如下（`run_id=20261119-162745-zhongji_2026-d677`）：

| 断言 | 动作 | 点答案 | 裁决集 | 后验 |
|---|---|---|---|---|
| 营业收入同比增速 | answer | 高于170% | 高于170% | 低140% .012 / 140-170% .042 / 高170% .945 |
| 归母净利润同比增速 | adjudicate | 190%至220% | 190%至220%, 高于220% | 低190% .112 / 190-220% .579 / 高220% .309 |
| 综合毛利率 | adjudicate | 45%至47% | 45%至47%, 高于47% | 低45% .084 / 45-47% .732 / 高47% .184 |
| 年报披露日期 | adjudicate | 晚于2027-04-15 | 不晚于2027-03-31, 晚于2027-04-15 | 不晚于3/31 .310 / 4/1-4/15 .134 / 晚于4/15 .557 |

披露日期的点估计为 2027-04-20，区间为 2027-03-25 至 2027-04-28。这个判断来自公司 2021 至 2024 年年报集中在 4 月 21 日至 25 日、2025 年年报提前到 2026-03-31 的混合证据，因此系统选择一个包含“3 月底”和“4 月下旬”的裁决集，而不是把最近一年的提前披露当成稳定规律。

审计报告位于：

```text
paper/results/anchor_cli/<run_id>/audit.md
paper/results/anchor_cli/<run_id>/audit.json
paper/results/anchor_cli/<run_id>/prompts/<claim_id>.txt
```

`audit.json` 包含每条证据的标题、URL、日期、提供者，每个锚点的原文引文、资格、可靠性、纠正记录，逐步信念轨迹，全部动作的期望损失，以及日期估计。`audit.md` 是同一内容的人类可读版本。

## 5. 复现与变化

网页检索结果会随时间和搜索引擎状态变化，因此不同运行日的证据集合可能不同。审计文件记录的是当次实际使用的证据，不能把某一次运行的后验当作固定输出。若要复现同一次运行，保留该次的 `audit.json` 和 `prompts/` 目录；LLM 请求按 payload 哈希缓存在 `paper/results/anchor_cli/llm_cache/`，相同 prompt 会命中缓存。

案例文件在 `configs/anchor_cases/`。新增一个案例只需要写一个 YAML，包含公司、代码、期间、断言、标签、阈值和检索词；引擎不包含公司分支。

## 6. 参数与实现审计（2026-11-20）

新易盛案例暴露了三类问题：检索预算被解析器查询挤占、360/Sogou 重定向链接在去重时被折叠、硬锚点在融合时被稀释。修正后，官方激励计划中的“2026 年营业收入不低于 500 亿元”可以进入证据链，季度结果不再被误当成“未发布指引”的证据。

| 参数或实现 | 修正前 | 修正后 | 影响 |
|---|---|---|---|
| `search.max_queries` | 4 | 8 | 为必需查询面和可选查询面留出空间 |
| `search.max_parser_queries` | 无 | 2 | 解析器查询最多两条，避免挤掉必需查询面 |
| `search.max_per_facet` | 无 | 2 | 单个查询面最多贡献两条，防止一词多投 |
| `search.max_evidence` | 6 | 8 | 容纳官方公告和多个查询的证据 |
| `search.max_chars_per_item` | 1800 | 2200 | 给抽取后的相关句子留出空间 |
| `search.query_facets` | 代码内固定顺序 | 配置驱动的查询面组合 | `latest_period`、`prior_period`、`forward_disclosure`、`industry`、`date_disclosure` |
| 覆盖检查 | 无 | 审计记录 `coverage_gaps` | 必需查询面无证据时显式提示 |
| `canonical_url` | 360/Sogou 重定向只保留路径 | 保留完整重定向 URL | 避免所有结果被合并成一条 |
| 证据选择 | 全局得分取前 N | 按查询轮转，官方优先 | 防止近重复报道占满名额 |
| 公告文本 | 截取前 N 字 | 句子级相关摘录 | 把深埋在 PDF 中的考核目标提到前面 |
| 硬锚点 | 融合前置 0.98 | 融合后再投影 | 避免 LLM 标签分数稀释硬约束 |
| 引文核验 | 对照截断后的全文 | 对照全文、提示摘录和摘要 | 公告 PDF 深部引文不再误判 |
| 披露类负标签 | 可由季度结果推出 | 需要明确“未发布”语句 | 季度业绩不能证明没有指引 |
| 数值输出 | 仅离散标签 | 增加辅助 `numeric_estimate` | CLI 可回答“会是多少”，但仍不参与动作选择 |

新易盛 2026 年全年营业收入案例的前后对比：

| 运行 | 断言 1（营收是否高于 2025） | 断言 2（是否发布 2026 全年指引） |
|---|---|---|
| 修正前 `20261119-235910-ask-369d` | 高于后验 0.828，未检索到三季报 | “未发布指引”后验 0.816 |
| 修正后 `20261120-011709-ask-2e5f` | 高于后验 0.983，桥接 424.67 亿元（年化，382.20 至 467.13），辅助数值 500 亿元 | “未明确发布但存在相关经营目标”后验 0.859，官方 500 亿元目标两条锚点 |

修正后的断言 2 使用巨潮资讯网 2026-08-21 的《2026 年限制性股票激励计划（草案）摘要》和同日法律意见书。激励目标是归属考核底线，不是管理层对实际值的点预测；标签因此是“未明确发布但存在相关经营目标”，不是“明确发布指引”。审计报告在锚点理由中保留“股权激励业绩考核目标”的限定，读者不应把它当作正式指引。

断言 1 的桥接是年化基线 `318.50 / 3 × 4 = 424.67`，不是管理层指引；辅助数值 500 亿元来自 LLM 对激励目标和订单信息的综合。两者并列显示，系统不把年化基线和 LLM 估计偷偷平均成一个看似精确的数。

### 历史校准与演化

CLI 的信念更新不是从一组手写先验开始。`scripts/train_anchor_calibration.py` 只使用验证集上已经揭示的结果和锚点，训练四类对象并写入一个可移植的 JSON 包：

- 标签先验，来自验证集结果分布，加平滑。
- 锚点类型的 Beta 可靠度，按类型统计“锚点隐含标签是否等于真实标签”，再做收缩。
- 一个小的 softmax 校准器，输入是锚点后验、标签分数、熵、间隔、锚点数量和可靠度特征。
- 温度参数和锚点后验与校准器的融合权重，二者都在验证集内部的校准切片上选择。

训练和选择不使用测试集结果；脚本只在最后计算测试集指标用于报告。校准包只作用于 `level` 和 `growth` 两类指标；毛利率、产能、产量和日期断言不做这套校准，因为它们的标签空间和数值桥不同。运行审计会写出 `calibration.applied`、温度、融合权重和先验来源，便于检查。

```bash
python scripts/train_anchor_calibration.py \
  --beliefs paper/results/evolution_v1/temporal_beliefs_new.jsonl \
  --anchors paper/results/evolution_v1/anchors_validation.jsonl \
  --config configs/anchor_cli.yaml \
  --out paper/results/anchor_cli/calibration/bundle.json
```

核心演化本身在 `experiments/evolution/temporal_fusion.py` 中实现：锚点类型的 Beta 可靠度按结果公开揭示日更新，截止日之后的揭示不进入当前断言。CLI 的校准包是这条历史训练链的一个可移植快照，不是逐条断言的在线学习器；它保存的是截至训练期末的类型可靠度和先验，而不是把 2026 年案例的结果写进参数。这个区别在跨市场使用时尤其重要：从美国收入指引验证集得到的先验和类型可靠度，迁移到 A 股案例时只作为弱先验，最终判断仍由本地证据锚点决定。

### 这不是按一个 case 调出来的常数

需要区分“针对新易盛调的常数”和“通用的预算机制”。`max_queries` 的具体数值仍然是一个配置项，任何固定预算都不可能覆盖所有领域；这次改的是预算的分配方式，而不是把 4 改成 6 或 8 就结束。

- 必需查询面 `latest_period`、`prior_period`、`date_disclosure` 先占位。解析器给三条泛化查询，也不能把它们挤掉。
- 解析器查询最多两条，放在必需查询面之后、可选查询面之前。
- 可选查询面 `forward_disclosure`、`industry` 用剩余预算填充。
- 换一个指标（毛利率、产能、披露日期）时，必需查询面仍然保留；不需要改代码。
- 如果新领域需要新的证据渠道（订单、监管审批、产能投放），在 `configs/anchor_cli.yaml` 的 `query_facets` 中增加一个 facet；这是配置扩展，不是 case 分支。
- 审计报告记录完整 query plan 和 `coverage_gaps`。某个必需查询面没有命中证据时，报告会显式写出，而不是静默地把它当成“没有证据”。

这仍然不是万能的。可选查询面在预算耗尽时会被丢弃，审计报告能说明哪些查询被选中，但不能自动知道某个未配置的渠道对这个行业是否重要。真正的通用做法是让查询面从断言的指标和披露类型自动生成，或者由解析器提出候选查询面；这需要在更多指标和市场上验证，当前版本先把“必需面不被挤掉”和“缺口可见”两件事做实。

## 7. 从锚点到数值模型

这部分回答“锚点怎么变成预测”，而不是让 LLM 直接给一个数。

### 7.1 三层分工

```text
断言解析（LLM）
  -> metric_kind / model_template / anchor_types / query_facets / thresholds
证据检索（确定性）
  -> 按查询面取证，官方公告优先
锚点抽取（LLM）
  -> numeric_value / numeric_unit / numeric_period / model_role
数值桥接（确定性代码）
  -> 按模板做算术，记录公式、输入、缺失项和区间来源
资格与信念（确定性）
  -> 引文核验、角色-期间校验、硬软判定、损失感知读出
```

LLM 只负责“这个数字是什么、属于哪个槽位”，不负责把数字算成结论。算术由 `scripts/forecast_bridge.py` 执行，公式和输入写入审计文件。这样即使模型想“听风是风”，它也必须把数字落到一个具体角色上，并接受引文和期间检查。

### 7.2 桥接模板

| 模板 | 公式 | 主要角色 | 适用 |
|---|---|---|---|
| `level_bridge` | YTD 实际 + Q4 预测；或 YTD + Q3 × 季节因子；或 YTD 年化 | `ytd_actual`, `q4_forecast`, `q3_revenue`, `seasonal_factor` | 全年收入、全年利润等水平量 |
| `growth_bridge` | 水平预测 / 上一年度实际 − 1 | 同上 + `prior_actual` | 同比增速 |
| `margin_bridge` | 当前毛利率 + 价格/结构变化 + 成本变化 | `current_margin`, `price_mix_delta`, `cost_delta` | 毛利率 |
| `capacity_bridge` | 当前产能 + 扩产 − 退役 | `current_capacity`, `expansion`, `retirement` | 产能 |
| `production_bridge` | 产能 × 利用率 × 良率 | `capacity`, `utilization`, `yield` | 产量、排产 |
| `date_window` | 日期窗口与历史披露记录 | `disclosure_history`, `appointment_disclosure`, `regulation` | 披露日期 |
| `disclosure_check` | 检查正式指引、激励目标、业绩预告 | `guidance`, `incentive_target`, `earnings_preview` | 是否发布指引 |

解析器为每条断言选择 `metric_kind` 和 `model_template`，并给出 `anchor_types` 与 `query_facets`。例如：

- 收入：`level_bridge` 或 `growth_bridge`，角色 `ytd_actual`、`prior_actual`、`q4_forecast`、`q3_revenue`、`seasonal_factor`、`consensus`、`fy_target`。
- 产能：`capacity_bridge`，角色 `current_capacity`、`expansion`、`retirement`、`utilization`。
- 排产/产量：`production_bridge`，角色 `capacity`、`utilization`、`yield`、`orders`、`seasonality`。
- 毛利率：`margin_bridge`，角色 `current_margin`、`prior_margin`、`price_mix_delta`、`cost_delta`。
- 是否发布指引：`disclosure_check`，角色 `guidance`、`incentive_target`、`earnings_preview`、`disclosure_history`。

### 7.3 非收入场景

**产能。** 断言“2026 年产能是否高于 2025 年”，解析器选择 `capacity_bridge`，查询面为当前产能、扩产项目、利用率、订单、行业需求。若锚点给出当前产能 100 万只、扩产 20 万只、退役 5 万只，桥接结果为：

```text
100 + 20 - 5 = 115 万只
```

这比让 LLM 直接说“产能会增长”更可检查：每个输入都有来源，公式固定。

**排产/产量。** 解析器选择 `production_bridge`，桥接为：

```text
产能 100 万只 × 利用率 85% × 良率 95% = 80.75 万只
```

如果利用率或良率缺失，桥接返回缺失项，不会用一个“拍脑袋”的数补上。

**毛利率。** 解析器选择 `margin_bridge`：

```text
当前毛利率 46.4% + 价格/结构 +0.5pp − 成本 0.3pp = 46.6%
```

注意 `current_margin` 必须是目标年份的最新期间；2025 年的 42.61% 只能进 `prior_margin`，不能冒充当前毛利率。角色与 `numeric_period` 不一致时，锚点会被降权并从桥接输入中排除。

**收入。** 新易盛案例的桥接输入是 2026 年前三季度营业收入 318.50 亿元，Q4 预测或季节因子未抽取到时，桥接回退到年化：

```text
318.50 / 3 × 4 = 424.67 亿元
```

这是一个保守的 run-rate 基线，不是管理层指引。审计报告同时显示 LLM 的辅助数值估计 500 亿元（450 至 550）。两者不一致时，读者可以看到：桥接是年化基线，LLM 估计受了 500 亿元激励目标影响。系统不把两者偷偷平均成一个看似精确的数。

### 7.4 防止“听风是风”

- `numeric_value` 必须能在引文中找到；找不到时锚点降权，且不进入桥接输入。
- `numeric_period` 必须与 `model_role` 一致：2025 年的数不能进 `ytd_actual` 或 `current_margin`，只能进 `prior_actual` 或 `prior_margin`。
- 公司目标 `fy_target` 和分析师一致预期 `consensus` 不作为桥接点预测。目标只是下限，一致预期是外部观点；桥接只用公司实际值 + 明确的 Q4 预测/季节因子/年化基线。
- 桥接锚点标记为 `model`，按软锚点进入信念更新，不会覆盖硬锚点和已核验的文本锚点。
- 输入不完整时，桥接返回 `missing`，审计报告显示缺失项，不用目标或一致预期填补。

当前实现的范围是有限的：它做的是数量桥接，不是完整的财务三表模型；没有做会计恒等式校验、行业产能约束、价格弹性和情景相关性。它的价值是把“锚点数字”变成可复核的算术，而不是让 LLM 直接给结论。

## 8. 边界

- 这个接口是研究框架的演示，不是交易系统，也不构成投资建议。
- 结果空间和阈值由用户或案例文件给出。阈值本身不合理时，框架只能在给定契约内做一致的推断。
- LLM 仍可能给出错误的锚点或错误的标签。逐字引文核验、日期投影、参考值锚点剔除和法定截止日剔除降低了这类错误，但不能消除。
- 网页来源可能缺失日期或被转载篡改。系统对无日期来源降权，并在审计报告中保留原始链接，供读者复核。
- 披露日期断言使用公告日期，公告日期与实际披露时点可能相差一天。
