# 中国公开数据轨道

## 1. 目的与主张边界

国内轨道不是把美国 SEC 结果翻译成中文，而是检验同一问题规划接口能否迁移到中国上市公司披露。它分为两个互不混分的子轨道：

1. **公开基准轨道**：复用 FinGLM 年报、人工问题和答案，评价中文实体—报告期义务、文档闭包、证据定位和答案；
2. **自行构建点时轨道**：从巨潮资讯、上交所和深交所公开披露补建半年报/季报、问询函—回复、并购进展、处罚整改等文档链，评价 `valid_time`、`available_at`、限制证据和继续/断言/拒答。

公开原题与自行构建题必须分别报告。FinGLM 单份年报问题不能冒充多文档、混合期间或点时证据闭包；FinGLM2 的问题文件也不能在数据库和答案缺失时冒充可完整评分的 RAG benchmark。

## 2. 已核验的公开数据

### 2.1 FinGLM

核验来源为 [MetaGLM/FinGLM](https://github.com/MetaGLM/FinGLM)，固定提交 `ff48a9dc5e6c7f9d9a9c6120024dccefd8cbaa80`。仓库 README 声明：

- 2019–2021 年中国上市公司年度报告 11,588 份；
- 初赛、复赛 A/B/C 累计人工标注问答 10,000 条；
- PDF 通过 ModelScope 发布，报告清单在 GitHub 仓库公开。

本地已取得并校验复赛 A 的 2,000 条问题、2,000 条答案以及完整报告清单。清单解析结果为：

| 字段 | 核验值 |
|---|---:|
| 年报 | 11,588 |
| 证券代码 | 4,366 |
| 2019 / 2020 / 2021 年报告 | 3,450 / 3,870 / 4,268 |
| 至少两年报告的证券代码 | 3,892 |
| 三年均有报告的证券代码 | 3,330 |
| 复赛 A 显式含“相比”的跨年题 | 9 |

这 9 道题均比较同一公司两个报告年度的法定代表人，适合做最小中国跨年义务 pilot；但它们模板单一、数量小，只能验证中文迁移和机制可运行性。

FinGLM 的许可证必须保守处理：GitHub API 未识别标准许可证，README 只写“相关资源仅供研究、交流使用，一般不建议商业用途”。因此论文只能写“按项目说明用于学术研究”，不能写成 Apache、MIT 或无条件开放许可。

### 2.2 FinGLM2

核验来源为 [MetaGLM/FinGLM2](https://github.com/MetaGLM/FinGLM2)，固定提交 `39cf08c54128e641eef3284f2b68d6d4c0fadb5d`，仓库默认协议为 Apache-2.0。

公开问题包含 101 组、311 个子问题；93 组含 3 个子问题，8 组含 4 个子问题。至少 45 组后续问题显式使用“该公司、该股、以上、这个概念”等上下文指代，天然适合诊断跨子问题状态保持和工具规划。

但仓库只公开问题、数据库 schema 和方案代码。比赛说明明确提到评测环境提供“比赛数据库”，该数据库和金标答案并未随仓库发布。因此当前用途是规划模板与无金标诊断，不是完整可复现的文档 RAG benchmark。

## 3. 已冻结的中国跨年 pilot

`preexperiments/china_public_data_pilot_manifest_v1.json` 在运行方法前冻结全部 9 道 FinGLM 复赛 A “相比”题：

- 开发集：qid 357、941、1178、1221；
- 冻结 pilot：qid 1493、1626、1863、1958、1976；
- 9 家公司互不重复；
- 每题为两个显式年份建立两条独立“证券代码—年度报告”义务；
- 不允许只读取较新年报中的上年对照列，就宣称两条文档路径均已闭合。

文档取得优先级为交易所/巨潮官方公告页，其次为 ModelScope FinGLM LFS 对象。每份文档保存原始 URL、公告日期、证券代码、报告期、文档类型、SHA-256 和下载状态。报告清单文件名中的日期只能作为候选公告日；正式点时实验必须回到官方页面核验。

当前 ModelScope Git 索引和 11,588 个 LFS 路径可访问，但指定 PDF 的 LFS 下载长时间无响应。改用巨潮官方公告接口后，9 道冻结跨年题所需的 18 份完整年报已全部取得，PDF 头和 SHA-256 均通过，下载失败为 0。开开实业在 FinGLM 中使用 B 股代码 900943，巨潮按 A 股代码 600272 索引；这一别名映射已显式写入采集日志。

18 份 PDF 已用 `pypdfium2` 转换为 3,567 个页级检索单元。9 道题的两份目标报告均存在经核验的证据页，证据页完整率为 9/9。方法运行前冻结了开发/测试划分、页级语料、检索预算、runner 和 SHA-256；冻结测试包含 qid 1493、1626、1863、1958、1976。

## 4. 页级公开 pilot 结果与裁决

冻结测试 5 题的文件闭包和页级证据闭包如下。所有方法共享 18 份文档、同一中文字符/二元组 BM25、4 次检索预算和报告期元数据；`HiREC-style` 是透明近似实现，不冒充原版 HiREC。reader 结果是字段 oracle 的页级覆盖诊断，不是真实 LLM reader 准确率。

| 方法 | 文件闭包 | 错误文档率 | 证据页闭包 |
|---|---:|---:|---:|
| Single-shot | 5/5 | 0.4667 | 5/5 |
| Fixed decomposition | 5/5 | 0 | 4/5 |
| Metadata decomposition | 5/5 | 0 | 5/5 |
| Generic adaptive period | 5/5 | 0 | 5/5 |
| HiREC-style period | 5/5 | 0 | 5/5 |
| FinPlan v1 entity-only | 0/5 | 0 | 0/5 |
| FinPlan entity-year no-path | 5/5 | 0 | 5/5 |
| FinPlan entity-year/path-bound | 5/5 | 0 | 5/5 |

相对原始 `entity-only` 版本，两个 `entity-year` 版本均有 5 个仅目标方法成功的样本，双侧 exact McNemar `p=0.0625`；相对 metadata decomposition、Generic adaptive period 和 HiREC-style period 均无不一致样本，`p=1.0`。因此该公开 pilot 支持的是“跨年比较必须把公司—年度拆成独立义务”这一表示必要性，而不是 FinPlan 策略的独立优势。Single-shot 也达到 5/5 闭包，但错误文档率为 0.4667，说明它用额外噪声换取了召回。

该结果不能单独验证总体 research gap：9 道题均为同一法定代表人比较模板，语料只含每题所需的两个年份及跨公司干扰，没有同公司额外年份、混合 filing、限制证据和点时拒答压力。下一阶段必须通过自行构建的中国机制轨道增加这些条件；若同元数据强基线继续追平，则贡献收缩为金融证据义务表示、benchmark 与审计协议。

### 4.1 金标质量审计

两道公开题存在“字符串不同但语义相同”的标签冲突，必须与检索失败分开报告：

- qid 357：`庄虔赟` 与 `庄虔贇` 为同一姓名的简繁字形差异；
- qid 1493：`Wang Xinglong` 与 `WANG XINGLONG` 仅大小写不同。

实验保留 FinGLM 原始字符串标签，同时另报经 NFKC、casefold 和已人工核验的 `贇→赟` 映射得到的语义标签；不覆盖原始答案，也不改变文档闭包金标。

### 4.2 混合期间(H1/Q3/FY)页级 pilot 结果与裁决

5 家公司、15 份文档(10 份 H1/Q3 + 5 份同年年报)、1,894 页的期间碰撞 pilot 已在方法运行前冻结(manifest `china_mixed_period_pilot_manifest_v1.json`,开发集 `cnmix-1493`、`cnmix-1626`,冻结集 `cnmix-1863`、`cnmix-1958`、`cnmix-1976`)。每题的语料刻意包含同公司同年第三期间报告作为同公司干扰项,因此 `security_code × fiscal_year` 义务键必然把两个目标期间折叠,预期在义务召回上失败。页级构建器与 runner 的 SHA-256(`data=8c354e…`、`runner=a0109a…`)在方法运行前由 runner 自记录进结果文件;期间词解析 bug(裸词"第三季度/半年度"未匹配、重叠词双计)只按题目文本与开发集诊断修复,冻结题结果未参与任何调整,修复后对 3 题冻结集一次性运行。

冻结 3 题结果(共享语料、BM25、budget=4、金标字段对方法隐藏;HiREC-style 为透明近似):

| 方法 | 义务召回 | 文件闭包 | 错误文档率 | 证据页召回/闭包 | 查询/文档 |
|---|---:|---:|---:|---:|---:|
| Single-shot | 0 | 3/3 | 0.500 | 0.833/0.67 | 1/4 |
| Fixed decomposition | 0 | 3/3 | 0 | 0.833/0.67 | 2/2 |
| Metadata decomposition | 1.0 | 3/3 | 0 | 0.833/0.67 | 2/2 |
| Generic adaptive | 0 | 3/3 | 0.333 | 0.833/0.67 | 3/3 |
| HiREC-style | 0 | 3/3 | 0.333 | 0.833/0.67 | 3/3 |
| FinPlan v1 entity-only | 0 | 0/3 | 0 | 0.333/0 | 1/1 |
| FinPlan entity-year | 0 | 0/3 | 0 | 0.333/0 | 1/1 |
| FinPlan period-aware | 1.0 | 3/3 | 0 | 0.833/0.67 | 2/2 |

配对 exact McNemar(文件闭包,冻结 3 题):period-aware 相对 entity-only 与 entity-year 各有 3 个仅目标方法成功的样本、双侧 `p=0.25`,方向明确但样本过小;相对 fixed/metadata/generic/HiREC 均无不一致样本、`p=1.0`。裁决与跨年 pilot 一致且更强:**本 pilot 支持"同公司同年不同财政期间必须进入义务键"的表示必要性(entity-only/entity-year 直接 0/3 失败),不支持 FinPlan 策略独立优势**。尤其注意 Fixed decomposition 仅靠题目自带的期间词即可 3/3 闭包且零错误文档——题目显式写出期间时,结构化期间键没有带来额外检索增益;Generic/HiREC 达到闭包但各含 1 个同公司干扰文档,成本更高。

证据页上限:3 题冻结集中 cnmix-1958(603577,Q3/FY)在所有闭包方法上证据页闭包均为 0——BM25 对该文档的首选页不在金标候选页(该年报的法定代表人在 10 个候选页出现,首选页为 p4),属于检索面伪影而非方法差异;因此字段 oracle 的页级覆盖不能写成真实 reader 答案正确率。开发 2 题诊断中 Fixed decomposition 闭包 0.5、其余闭包方法与 metadata 一致,修复后的冻结结果未再反哺开发。

### 4.3 答案层(reader)冻结运行与 coverage–risk 裁决

2026-08-11 在冻结检索轨迹上完成真实答案层运行(`preexperiments/read_china_mixed_period_pilot.py`,冻结哈希自记录于 `preexperiments/results/china_mixed_period_reader_v1.json`)。答案层只读各方法实际检索到的页面,不使用金标;期间归属来自文档 id 后缀与题目期间词;reader 按冻结规划器的主体解析做主体接地(排除其他公司的污染文档,不构成金标泄漏)。

**主答案层(确定性抽取 + 规范化相等,冻结 3 题):**

| 方法 | 断言覆盖 | 断言正确率 | 拒答 |
|---|---:|---:|---:|
| Single-shot | 2/3 | 1.0 | 1 |
| Fixed / Metadata / Generic / HiREC | 2/3 | 1.0 | 1 |
| FinPlan period-aware | 2/3 | 1.0 | 1 |
| FinPlan v1 entity-only / entity-year | 0/3 | — | 3 |

- 断言正确率为 1.0(2 题:600418、600171 的 H1/FY 均正确读出同一人);唯一拒答为 cnmix-1958——所有方法的 FY 检索页含"法定代表人"关键词但姓名无法锚定抽取,答案层诚实拒答。该案例在文件闭包层面全部方法都是 3/3,**答案层直接暴露"文件闭包 ≠ 答案正确率"**;
- entity-only/entity-year 覆盖为 0:永远只有单期文档,答案层全部拒答——把规划层的闭包失败转化成了可度量的选择性损失;
- 跨公司污染已由主体接地过滤(如 single_shot 拉入其他公司 Q3/H1 文档,`pages_filtered` 逐行记录)。

**诊断层(Qwen2.5-0.5B 自由判定):** 开发集上三种 prompt 变体对相同证据给出矛盾判定(v1 最贴近证据但仍过度断言,单文档证据也断言"相同");冻结集上 entity-only/entity-year 仍断言 2/3、generic/HiREC/single-shot 断言正确率 0.333。结论:**0.5B 弱模型的结构化判定不可靠,只作鲁棒性诊断,不作主答案指标**;论文 reader 层需更强模型,并优先采用"抽取 + 确定性相等"的跨度方案。

**A7 停止策略消融(fill-to-budget 对照,新消融不在冻结记录内):** 确定性层上 stop-at-closure(2 文档)与用满预算(4 文档)答案结果完全相同(2/3 断言全对 + 同 1 拒答),只多花 2 次检索;LLM 诊断层上 fill 使 period-aware 断言正确率从 0.5 降到 0.333(额外干扰页损害弱 reader)。小样本内不支持"用满预算换准确率"。

## 5. 自行构建的国内机制数据

FinGLM 只有年度报告，无法识别美国 validation5/6 已暴露的“同公司同年不同财政期间碰撞”，也没有限制证据和严格 `available_at`。国内补建集至少覆盖：

1. 年报—半年报—季报混合问题；
2. 交易所问询函—公司回复；
3. 并购预案—审核/问询—进展—完成或终止；
4. 重大诉讼、担保、关联交易的后续变化；
5. 监管处罚—整改公告；
6. 截止时点前证据不足而应继续检索或拒答的样本。

每个样本最少保存：`query_id, security_code, entity, cutoff, valid_time, available_at, document_type, source_url, sha256, obligations, evidence_spans, limiting_spans, answerability`。公告修订、摘要转载和同一原件镜像必须归入同一 provenance family，防止把重复来源计作独立证据。

## 6. 基线、指标与实验顺序

国内轨道沿用相同预算和元数据的公平比较：single-shot、固定分解、period metadata decomposition、Generic adaptive、HiREC-style 和 FinPlan period-aware。先做文件闭包，再做真实 reader，最后做停止/拒答；不把三者合并成一个不可诊断的总分。

主要指标：

- 主体—年度/期间义务 recall、exact；
- 文档闭包、错误文档率、future leakage；
- 证据跨度 recall、引用正确率、数值/关系答案准确率；
- 限制证据召回、过度断言率、应答/拒答校准；
- 查询次数、读取文档数和 token 成本。

公开 pilot 已按“开发 4 题—冻结代码和阈值—运行剩余 5 题”完成。下一阶段先为同一公司加入第三年度年报和半年报/季报作为期间干扰，再扩展问询、并购和处罚整改链。每批在运行方法前按公司、交易 lineage 和公告链切分，并冻结 `valid_time`、`available_at`、`cutoff` 与停止/拒答标签。公开 9 题只支持工程可行性和表示诊断，不支持统计显著性或 SOTA。
