# 消融、压力测试与 Go/No-Go

## 1. 组件消融

| 消融 | 移除内容 | 要识别的因果问题 |
|---|---|---|
| `–Path State` | 多条路径合并为一条自然语言轨迹 | 独立路径是否减少证据串线 |
| `–Obligations` | 不维护缺失/部分/闭合槽位 | 证据义务是否改善闭包和停止 |
| `–Limiting Evidence` | 不主动检索终止、撤回、失效等证据 | 安全提升是否来自反证轨道 |
| `–Available Time` | 只保留事实时间 | 历史认知泄漏是否真实存在 |
| `–Lineage` | 不做同源转载去重 | 多来源假象是否导致过度断言 |
| `–Conflict Action` | 冲突直接按最高分覆盖 | 显式核验动作是否有用 |
| `–Learned Policy` | 替换为固定 value-of-information 顺序 | 学习策略是否超过透明规则 |
| `–Stop Policy` | 固定用满预算 | 状态驱动停止是否降低成本 |
| `Generic Actions` | 保留状态，移除关系合法动作屏蔽 | 金融关系约束是否有独立价值 |

每个消融均共享语料和检索结果候选流。不能通过为完整模型开放更多候选文档来制造优势。

## 2. 压力测试

- **多路径**：同一主体存在多个交易、子公司或同名资产；
- **限制证据密集**：签署后终止、许可撤回、资产处置；
- **证据稀疏**：关键附件缺失或只出现间接证据；
- **来源冲突**：新闻、公司稿与监管文件状态不一致；
- **未来修订**：截止日后出现高相关性完成/终止文件；
- **谱系复制**：多篇转载指向同一原始稿；
- **关系外推**：训练只见收购/控制，测试许可或供应；
- **预算压缩**：2/4/6/10 次检索及不同 token 上限；
- **检索器增强**：从 BM25 到 hybrid/强 reranker，检验规划增益是否仍在。
- **filing 粒度碰撞**：同一公司、同一财政年度同时需要 Q1/Q2/Q3/FY，或跨年度比较同一季度；检验实体—年份状态是否错误合并独立义务。

## 3. Go/No-Go 门

### G1 真实现象门

在原子证据 Recall@20 达到可接受水平后，强通用 agent 仍有显著路径混淆、限制证据遗漏或 future leakage。若没有，停止“金融规划 gap”主张。

### G2 显式状态门

`same-state-generic-agent` 相对自然语言轨迹在闭包、固定覆盖风险或成本上有稳定增益。若没有，状态表示不构成贡献。

### G3 学习策略门

学习策略在 company-OOD/time-OOD 上超过 fixed relation-state planner 和 HiREC-style complementary query，并保持相当安全性。若没有，方法退回透明规则，不声称算法学习创新。

### G4 限制证据门

主动限制证据在预设 coverage/risk 条件下显著降低 overclaim，且额外成本可接受。若只降低覆盖而未改善风险，删除该模块。

### G5 点时门

移除 `available_at` 后 future leakage 显著上升，且影响答案或选择性风险。若只有合成数据成立，不能作为真实金融贡献。

### G6 OOD 与模板成本门

跨公司或跨时间仍有增益，且建立/维护关系模板的人工成本低于其风险或查询节省。若只能在同公司同交易内有效，结论必须收窄。

### G7 金融域轨道门

至少在生命周期关系与一条会计推导、点时指标或比较调查轨道上，状态接口相对自然语言轨迹仍改善闭包、选择性风险或成本；否则不得使用“金融域通用”表述，只保留单轨道结果。

### G8 filing/period 表示门

在包含 10-K、10-Q 和同年多期间的任务上，显式义务必须保持主体、filing type、财政年度和财政期间的独立性，并在新的冻结集超过实体—年份消融。若强 HiREC/Generic 在获得相同 filing 元数据后追平，则只保留表示和审计贡献，不声称 FinPlan 策略优势。

当前裁决：**G1 的部分现象得到真实支持，G8 发现明确旧框架失败，其余仍未通过**。

- 10-K 轨道中，无路径闭包缺口跨 BM25/BGE/RRF 复现，但路径绑定 FinPlan 与元数据和 Generic 强基线持平；
- 第三批非 oracle company/file-OOD 中，v4 相对旧规则由 15/22 改善到 18/22，双侧 p=.25，未达到确认性优势；
- 第四批 legacy-year 冻结集上，v1、v4、v5 均为 3/6，说明时间规划仍不能迁移；v6 的 6/6 是错误驱动开发结果；
- 第五批混合 10-K/10-Q 冻结集上，冻结 v6 的主体 exact 为 8/8，但义务召回为 0、闭包 4/8；FinPlan v3 路径绑定为 5/8，弱于 HiREC-style 路径绑定 7/8；
- filing/period-aware v7 在参与开发的第五批为 8/8；在新冻结 validation6 为 6/8，与元数据分解持平，低于 Generic/HiREC-style period 的 7/8。三道多 filing 题均闭包但样本过少，当前只保留表示贡献候选，不保留策略优势主张；
- 中国公开轨道已完成 9 道 FinGLM 跨年题、18 份巨潮年报和 3,567 页语料的冻结 pilot。测试集上 entity-only FinPlan 闭包 0/5，entity-year 为 5/5，但 metadata decomposition、Generic 和 HiREC-style 同为 5/5；这通过“义务表示诊断”，没有通过“策略独立优势”。Single-shot 错误文档率为 0.4667。该题集没有混合 filing、限制证据和拒答压力，不能单独通过 G1、G2 或 G7；FinGLM2 缺比赛数据库和答案，只能作规划诊断。
- 中国机制轨道已冻结 5 家公司的同年 H1/Q3/FY 期间碰撞协议，并取得 10 份巨潮 H1/Q3 报告；页级证据与方法尚未运行，因此目前只记录为数据就绪，不改变 G1/G2/G7 裁决。

## 4. 论文形态的预先裁决

| 真实结果 | 允许的论文定位 |
|---|---|
| 状态、学习策略与点时模块均过门 | 金融应用层 + RAG 规划算法论文 |
| 状态有效、学习策略不过门 | 显式状态/约束规划方法论文，不声称 learned planner 优越 |
| fixed planner 已达同一 Pareto 前沿 | benchmark、审计状态与安全协议论文 |
| 只在合成实验有效 | 不投稿主张真实金融价值；继续重做数据或停止项目 |
| 原子证据召回过低 | 先解决检索/数据，不把失败归因于规划 |
| 只在生命周期关系上过门 | 保留金融关系规划，但删除“金融域通用”措辞 |

## 5. 预实验到正式实验的顺序

1. 受控仿真排除明显无效组件；
2. 30 个 SEC 交易 lineage 的可行性预检；
3. 100–150 例人工 pilot，先复现实象门；
4. 冻结标签、模板和检索协议后扩充 benchmark；
5. 固定 planner、通用 agent 与 HiREC-style 基线先行；
6. 只有 G1–G2 成立才训练学习策略；
7. 最终测试集只运行冻结版本，并公开失败案例与拒答轨迹。
